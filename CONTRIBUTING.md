Contributing Guidelines

1. Branch Rules
Keep the main branch stable.
Create a feature branch for every new task.
Use descriptive branch names, such as feature/add-documentation.

2. Commit Rules
Write clear, meaningful commit messages.
Use the imperative mood, for example: Add project documentation.
Make small commits that focus on one change.

3. Pull Request Rules
Open a pull request before merging changes into main.
Explain what changed and why.
Link the related GitHub issue.
Request a review before merging.

4. Testing Rules
Test changes before opening a pull request.
Document the tests performed.
Fix any failures before requesting approval.

5. Merge Rules
Merge only after required checks pass and the review is approved.
Resolve merge conflicts before merging.
Do not push unreviewed changes directly to main.
